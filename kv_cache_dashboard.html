Why A100 is memory-bandwidth-bound during decode
During each decode step, the GPU must read the entire KV cache from HBM. With BF16, a 4K-token context in a 7B-param model needs ~8 GB of reads per step. At A100's 2 TB/s peak bandwidth, that's 4ms just in memory reads — before any compute.

INT8 Quantization — step by step
1

Compute K and V projections

For each new token, the hidden state passes through two linear layers to produce K and V vectors of shape [n_heads, head_dim]. These are BF16 activations that can span a wide dynamic range.

2

Per-token absmax scaling

For each head: scale = max(|k|) / 127
This captures the exact dynamic range of this specific token's key vector. A token with large values gets a large scale; quiet tokens get a small scale.

3

Quantize to INT8

k_int8 = round(k / scale).clamp(-127, 127)
Now each float (2 bytes) becomes an int8 (1 byte). Store k_int8 and scale in the cache.

4

Dequantize on read

Before attention: k_fp = k_int8.float() * scale
This reconstructs a BF16-compatible tensor. The attention kernel sees normal floats — no special handling needed in the matmul.

Quantization error anatomy

The error comes from rounding to 256 discrete levels. The scale factor controls how wide each "bucket" is.

10
Drag to see how scale affects quantization error. Large scale → coarse buckets → more error. Small scale → fine buckets but clips outliers.

INT8 vs FP8 tradeoff

INT8 uses uniform quantization — all 256 levels are equally spaced. Needs a scale per token (extra 4 bytes). Great for values that cluster near zero.


FP8 e4m3 uses non-uniform quantization — more precision near zero, less at extremes (like regular floats). Handles outliers better without per-token scales. H100 has native FP8 tensor cores.


Why not INT4? KV activations have more outliers than weights. KIVI (2024) showed INT2 is possible for recent tokens if you keep the "attention sink" tokens in BF16.

Annotated code — INT8 quantize kernel
def _quantize(self, x: torch.Tensor):
    # x shape: [batch, n_heads, head_dim]
    # Goal: map each float in x to int8, preserving relative magnitudes

    # Step 1: find the maximum absolute value per head (keepdim for broadcast)
    scale = x.abs().max(dim=-1, keepdim=True).values / 127.0
    #  ↑ shape: [batch, n_heads, 1]  ← one scale per (batch item, attention head)
    #  Dividing by 127 maps the max value to ±127 in INT8

    scale = scale.clamp(min=1e-8)
    #  ↑ Avoid division by zero for all-zero tensors

    # Step 2: divide by scale → values now in [-127, 127] range
    #         round → snap to integer grid
    #         clamp → safety clip (shouldn't be needed with absmax)
    #         .to(int8) → cast to 1-byte integer
    x_q = (x / scale).round().clamp(-127, 127).to(torch.int8)

    return x_q, scale.squeeze(-1)
    #  ↑ scale shape: [batch, n_heads]  ← stored alongside x_q in cache

# Dequantize (on read, before attention):
k = (k_int8.float() * scale.unsqueeze(-1)).to(torch.bfloat16)
#         ↑ reverse the scale                   ↑ back to BF16 for attention matmul
